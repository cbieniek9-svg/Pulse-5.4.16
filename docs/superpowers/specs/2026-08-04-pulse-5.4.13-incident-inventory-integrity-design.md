# Pulse 5.4.13 Incident and Inventory Integrity Design

## Goal

Release Pulse 5.4.13 so submitted incident investigations cannot be silently rewritten, signature roles cannot be forged by any Safe user, attach/sign/amend actions are audited, and inventory count sessions require an explicit permission with no committed-line drift against `backstock_on_hand`. Preserve 5.4.10–5.4.12 financial, security, and backup controls.

## Scope

In scope:

- Fail-closed investigation mutations after submit (API matches UI).
- One-time submit that freezes `submitted_by` / `submitted_at`.
- Manager-only reopen/amend path with append-only history and audit.
- Role-bound signatures with server-stamped signer identity.
- Audit coverage for patch, attach, delete, sign, submit, and reopen.
- New clerk permission `inventory`; managers always allowed.
- Committed inventory sessions reject line edit/delete/scan; reopen clears that session’s `backstock_on_hand`; re-commit rewrites memory.
- Additive migration 062 and full test coverage through packaging.

Out of scope (later releases):

- 5.4.14 spreadsheet parser replacement (`xlsx`) and remaining dependency audit cleanup.
- Broader Safe portal redesign, new investigation PDF fields, or inventory UX overhaul beyond permission/immutability mirroring.

## Policies Chosen

1. **Investigations after submit:** hard-locked for clerks; Manager / Store Manager may reopen/amend via an audited path. Original submit metadata stays frozen.
2. **Signatures:** Lead = any Safe user; Safety Committee / Senior Management = Manager or Store Manager only. Server stamps signer name (and date) from the authenticated session; client-forged identity is rejected.
3. **Inventory access:** new staff permission `inventory`. Managers always pass. CREATE / scan / edit-open / CLOSE & COMMIT / reopen / finalize all use the same gate (`inventory` or manager).
4. **Committed sessions:** forbid line mutations while status ≠ `open`. Reopen clears `backstock_on_hand` rows for that `source_session_id`. Memory is rewritten only on CLOSE & COMMIT.

## Architecture

### Incident investigations

Primary modules:

- `src/lib/incident-investigations.cjs` — draft-only mutation gates; one-shot submit; reopen/amend; role checks on signatures.
- `src/routes/manager/incident-investigations.cjs` — HTTP status/codes; manager gate for reopen; audit wiring.
- `src/lib/staff-permissions.cjs` — reuse `canAccessSafeInspections` / `isManagerRole`; no new Safe permission required.
- `client/src/safe/components/InvestigateWizard.jsx` (+ `safeApi.js`) — hide mutate controls when locked; manager reopen control; surface error codes.
- Reference immutability pattern: `src/lib/safety-inspections.cjs` (draft-only after submit).

Status model:

```text
create → draft
  mutate (patch/attach/delete/sign) only while draft
  first submit → submitted  (set submitted_by / submitted_at; never overwrite later)
manager reopen → draft
  mutate again while draft
  submit after amend → submitted  (set last_submitted_by / last_submitted_at only;
                                   append amend/submit event; original submitted_* unchanged)
```

**Submit freeze rule (normative):**

- First successful submit sets `submitted_by` / `submitted_at` and these columns are **never overwritten**.
- Migration 062 adds `last_submitted_by` / `last_submitted_at` (nullable) for post-amend submits.
- Every reopen and every submit appends a row to `incident_investigation_amend_events` (or equivalent) with actor, action (`reopen`|`submit`), and timestamp.
- Resubmit without reopen remains rejected (`INVESTIGATION_ALREADY_SUBMITTED`).

**Signature roles:**

| Role key | Who may sign |
|----------|----------------|
| `lead` | Any session with Safe access |
| `safety_committee` | Manager / Store Manager |
| `senior_management` | Manager / Store Manager |

On sign: validate role; require PNG data URL; stamp `name` from session; stamp `date` server-side (store date or ISO); persist signature file; audit.

**Locked operations when `status !== 'draft'` (non-manager mutate paths):**

- PATCH investigation
- POST/DELETE attachments
- POST signatures
- POST submit (also rejects non-draft with `INVESTIGATION_ALREADY_SUBMITTED`)

Manager-only:

- `POST /api/safety/investigations/:id/reopen` → returns investigation to `draft`, writes amend event, audit `incident_investigation_reopened`.

**Audit actions (minimum):**

- `incident_investigation_created` (existing)
- `incident_investigation_updated` (new on PATCH)
- `incident_investigation_submitted` (existing; include whether first or post-amend)
- `incident_investigation_reopened` (new)
- `incident_investigation_attachment_added` / `_deleted` (new)
- `incident_investigation_signed` (new; include role)
- `incident_investigation_exported` (existing)

### Inventory count

Primary modules:

- `src/lib/staff-permissions.cjs` — add `{ key: 'inventory', label: '...' }` to `CLERK_PERMISSIONS`; helper `canAccessInventoryCount`.
- `src/routes/manager/inventory-count.cjs` — replace “any login” auth with permission check.
- `src/lib/inventory-count.cjs` — reject line/scan mutations unless session `open`; reopen clears memory for `source_session_id`.
- Client count app — hide editors when not open; show permission errors.
- `tests/inventory-count.test.cjs` — invert prior “edit after export/commit OK” contract where it conflicts.

Auth gate:

```text
requireCountAuth:
  requireSession(...)
  feature Inventory_Count_Enabled (unchanged)
  hasStaffPermission(db, session, 'inventory')  // managers always true
```

Public `GET /api/inventory/config` may remain unauthenticated for feature discovery, but must not expose session-management capabilities.

Committed immutability:

- `updateLine` / `deleteLine` / scan-insert fail with `INVENTORY_SESSION_LOCKED` when session status is not `open`.
- UI must not present editable line controls for non-open sessions.
- `reopenSession`: set status `open` and `DELETE FROM backstock_on_hand WHERE source_session_id = ?`.
- CLOSE & COMMIT: existing rewrite of location memory retained.

Default permission seeding (migration / `defaultPermissionsForRole`):

- Do **not** grant `inventory` to all existing clerks automatically (fail closed).
- Managers continue to pass via role.
- Deploy notes: store must grant `inventory` on staff rows that should count.
- Optional: Premium Clerk default for **new** hires may include `inventory` only if product wants parity with receiving — default recommendation is **no automatic grant** on upgrade.

## Error Contract

| Code | Typical HTTP | Meaning |
|------|--------------|---------|
| `INVESTIGATION_LOCKED` | 409 | Mutate/attach/sign while not draft |
| `INVESTIGATION_ALREADY_SUBMITTED` | 409 | Submit when not draft |
| `INVESTIGATION_REOPEN_FORBIDDEN` | 403 | Non-manager reopen |
| `SIGNATURE_ROLE_FORBIDDEN` | 403 | Session cannot sign that role |
| `INVENTORY_PERMISSION_REQUIRED` | 403 | Feature lacks `inventory` and is not manager |
| `INVENTORY_SESSION_LOCKED` | 409 | Line/scan mutation on non-open session |

Messages must say what to do next (reopen as manager; grant permission; complete open session) without implying a write succeeded.

## Migration 062

Additive and idempotent. Intended contents:

- Investigation amend/history support (table or first-submit columns + event log).
- Ensure staff permission catalog / UI list includes `inventory` (code constant + any DB seed if used).
- No mass rewrite of investigation payloads or inventory lines.
- Existing submitted investigations become API-immutable until manager reopen.
- Existing committed sessions become line-immutable until reopen (which clears memory).

Exact schema names may follow existing conventions; behavior above is normative.

## UI / Operator Surface

- Investigate wizard: read-only when submitted; manager sees Reopen; signature pads disabled for roles the session cannot sign; errors show `code` + message.
- Staff permissions editor: show `inventory` checkbox alongside receiving/safe.
- Count app: non-open sessions not editable; 403/409 surfaced clearly.
- Deploy notes: grant `inventory` intentionally; investigations lock after submit; managers reopen to amend.

## Test Strategy

Every behavior change is red-green. Minimum coverage:

1. PATCH / attach / sign after submit → `INVESTIGATION_LOCKED` (409).
2. Second submit without reopen → `INVESTIGATION_ALREADY_SUBMITTED`; original `submitted_by` / `submitted_at` unchanged.
3. Clerk cannot sign `senior_management` / `safety_committee` → `SIGNATURE_ROLE_FORBIDDEN`.
4. Manager can sign those roles; signature name matches session.
5. Non-manager reopen → 403; manager reopen → draft + audit + history.
6. Attach/sign/patch produce audit rows.
7. Clerk without `inventory` → 403 on session create/list mutate paths.
8. Clerk with `inventory` can open-session scan/edit/commit.
9. Committed `updateLine` → `INVENTORY_SESSION_LOCKED`; `backstock_on_hand` unchanged (5 stays 5).
10. Reopen clears `source_session_id` memory; re-commit writes new qty (5→99 only after commit).
11. Receiving Book + 5.4.11 security + 5.4.12 backup regressions remain green.

## Rollout Notes

- After upgrade, submitted investigations are locked until a manager reopens.
- Inventory clerks need explicit `inventory` permission (managers unaffected).
- Reopening a committed backstock session clears that session’s contribution to on-hand memory until re-commit — operators must re-commit before order finalize uses the new counts.
