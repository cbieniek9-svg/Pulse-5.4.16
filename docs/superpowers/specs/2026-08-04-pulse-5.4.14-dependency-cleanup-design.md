# Pulse 5.4.14 Dependency Cleanup Design

## Goal

Release Pulse 5.4.14 so the vulnerable community SheetJS package `xlsx@0.18.5` is removed from the dependency tree, spreadsheet imports continue to support both modern `.xlsx` and SMS legacy `.xls`, and investigation attachment uploads run on supported `multer` 2.x. Preserve 5.4.10–5.4.13 financial, security, backup, and integrity controls.

## Scope

In scope:

- Remove direct dependency on community `xlsx` (^0.18.5).
- Introduce one internal spreadsheet-read adapter used by all former `xlsx` call sites.
- Route `.xlsx` (OOXML) reads through existing `exceljs`.
- Route `.xls` (BIFF8) reads through a dedicated small BIFF reader (`xls-reader` or equivalent after a short spike confirming SMS fixture compatibility).
- Replace `XLSX.SSF` / `sheet_to_json` helpers with adapter utilities (Excel serial dates, sheet→objects).
- Upgrade `multer` from `1.4.5-lts.2` to a current 2.x release; keep disk storage, MIME allowlist, size limits, and investigation attach behavior.
- Update tests/fixtures that require `xlsx` for writing sample workbooks to ExcelJS (or adapter test helpers).
- Version bump to 5.4.14 and deploy packaging.

Out of scope:

- SheetJS Pro / CDN-only SheetJS installs.
- Changing ExcelJS export/write paths (store-transfer invoice/manifest, receiving report export).
- Full npm-audit chase of transitive findings (e.g. `tar` via `@electron/rebuild`) unless they block install.
- Product redesign of SMS import UX beyond clearer parse errors.
- Schema/data migrations unless deploy tooling requires a no-op 063 for bookkeeping (prefer no DB migration).

## Policies Chosen

1. **Hybrid spreadsheet stack:** ExcelJS for `.xlsx`; dedicated BIFF reader for `.xls`; remove community `xlsx`.
2. **Keep `.xls` support** for SMS catalog / shrink / schedule / markdown workflows (not “reject save-as only”).
3. **Multer 2.x** in the same release as the spreadsheet swap.
4. **Fail closed** on unsupported formats, corrupt buffers, or BIFF variants the dedicated reader cannot parse — clear operator message suggesting `.xlsx`/CSV when appropriate.

## Architecture

### Spreadsheet read adapter

Primary module: `src/lib/spreadsheet-read.cjs` (name may match repo style).

Responsibilities:

1. Detect format from filename extension and/or magic bytes (ZIP/OOXML vs OLE/CFB BIFF).
2. Parse via ExcelJS (`.xlsx`) or BIFF reader (`.xls`).
3. Normalize to a stable shape, e.g.:

```text
{
  format: 'xlsx' | 'xls',
  sheets: [ { name: string, rows: any[][] } ], // 0-based dense rows of cell values
}
```

4. Provide helpers used by call sites today:
   - `sheetToObjects(sheet, opts)` — header-row → objects (SheetJS `sheet_to_json` equivalent)
   - `excelSerialToDate(n)` — replace `XLSX.SSF.parse_date_code` for schedule imports
   - `readSpreadsheetFile(path)` / `readSpreadsheetBuffer(buf, filename)`

Call sites migrate off `require('xlsx')`:

| Module | Current use | Target |
|--------|-------------|--------|
| `store-transfers.cjs` | Customers sheet read | Adapter + ExcelJS path (file is `.xlsx`) |
| `edmonton-receiving-workbook-import.cjs` | Full workbook import | Adapter |
| `item-catalog.cjs` | SMS `.xls`/`.xlsx` catalog | Adapter |
| `floor-shrink.cjs` | Inventory count report | Adapter |
| `staff-schedule-import.cjs` | Schedule + serial dates | Adapter + date helper |
| `markdown-excel-import.cjs` | Kill-date rows | Adapter |
| `scripts/extract-excel-predecessor-data.cjs` | Offline extract | Adapter (dev/ops script) |

Writes remain on ExcelJS only. Tests that currently `XLSX.write` fixtures must use ExcelJS write or checked-in binary fixtures.

### BIFF reader selection

Preferred candidate: `xls-reader` (MIT, zero runtime deps, BIFF8, npm-published). Spike before lock:

- Parse existing SMS/catalog/shrink/schedule test fixtures (or representative store samples).
- Confirm multi-sheet + shared-string cells needed by catalog/shrink.
- If spike fails, evaluate `@stackline/xlsx` **only for `.xls`** as fallback — still remove community `0.18.5`; do not reintroduce unfixed `xlsx` from npm.

Adapter must not re-export a full SheetJS API surface.

### Multer 2.x

- Bump `multer` dependency to current 2.x.
- Update `src/routes/manager/incident-investigations.cjs` (and any other multer usage) for API differences (storage/fileFilter/limits stay equivalent).
- Preserve: 10 MB limit, JPEG/PNG/WebP/PDF only, max 30 attachments, draft-lock behavior from 5.4.13.
- Regression: unit/route test for successful attach + locked attach after submit.

### Error contract

| Code | Typical HTTP | Meaning |
|------|--------------|---------|
| `SPREADSHEET_UNSUPPORTED` | 400 | Extension/magic not `.xls`/`.xlsx` (or unsupported BIFF) |
| `SPREADSHEET_PARSE_FAILED` | 400 | Corrupt or unreadable workbook |
| (existing attach codes) | unchanged | Multer/MIME/size failures keep clear messages |

### Version / packaging

- Bump every active version reference **5.4.13 → 5.4.14**.
- Prefer **no** numbered SQL migration; `databaseUserVersion` stays **62** unless release tooling forbids it — if a migration file is required for process consistency, add empty/idempotent `063_dependency_cleanup_marker.cjs` that only records intent (no schema change). Decision at plan time: match prior “dependency-only” practice; if `release-manifest` requires `latestMigration` bump, use no-op 063.
- Target archive: `resources-deploy-5.4.14-no-service-xml.zip`.
- Do not edit machine service XML.

## Test Strategy

Red-green for every call-site migration:

1. Adapter reads a minimal `.xlsx` buffer via ExcelJS path.
2. Adapter reads a minimal/fixture `.xls` via BIFF path.
3. Unsupported type → `SPREADSHEET_UNSUPPORTED`.
4. Store-transfer customer list works without `require('xlsx')`.
5. Receiving workbook import fixtures still import.
6. Item-catalog / floor-shrink / schedule / markdown Excel fixtures still parse (including at least one `.xls` where historically required).
7. No production `src/**` file `require('xlsx')`; `package.json` has no `xlsx` dependency.
8. Multer 2 attachment upload success + 5.4.13 lock still holds.
9. `npm audit` no longer reports GHSA entries against community `xlsx` (document remaining unrelated findings).
10. Receiving financial, 5.4.11 security, 5.4.12 backup, 5.4.13 investigation/inventory suites remain green.

## Deploy / operator notes

- SMS `.xls` remains supported when BIFF8-compatible.
- If an ancient BIFF5/mislabeled HTML-as-xls file fails: save as `.xlsx` or CSV and retry.
- Attachment uploads unchanged for operators; server library upgrade only.

## Rollout risk

- Highest risk: SMS `.xls` edge cases (formulas-as-values, date serials, multi-sheet). Mitigate with fixture parity tests before removing `xlsx`.
- Multer 2: middleware API drift — cover with attach regression.
- Dual-parser bugs: keep format detection strict; never feed `.xlsx` bytes to BIFF reader or `.xls` to ExcelJS.
