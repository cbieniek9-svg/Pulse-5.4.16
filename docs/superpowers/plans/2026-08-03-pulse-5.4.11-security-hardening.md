# Pulse 5.4.11 Security Hardening Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Ship Pulse 5.4.11 with no default privileged training account, no self-asserted station writers, token-only purpose-bound devices, least-privilege TV sync, strict account revocation, HTTPS-only LAN access, and non-fatal adapter discovery.

**Architecture:** Add migration 060 and a centralized device-purpose policy. Keep staff sessions and device tokens as the only normal credentials, bind HTTP to loopback for Electron, expose LAN traffic only through HTTPS, and make actual TLS listener health authoritative. Implement every vulnerability as a red-green test before changing production behavior.

**Tech Stack:** CommonJS Node/Electron, Express 5, SQLite/better-sqlite3, React 19, Playwright 1.60, Node test runner.

- [ ] **Step 2: Add the shared safe enumerator**

```javascript
function listPrivateIpv4({ networkInterfaces = os.networkInterfaces } = {}) {
    try {
        return { addresses: normalize(networkInterfaces()), warning: '' };
    } catch (error) {
        return { addresses: [], warning: `Network adapter enumeration failed: ${error.message}` };
    }
}
```

Use it in both network config and certificate SAN generation.

- [ ] **Step 4: Make HTTPS listener state authoritative**

- set boot health `HTTPS_STARTUP_FAILED`;
- mark LAN readiness false;
- do not advertise LAN HTTP;
- ensure returned `networkConfig.https_active` reflects the actual listener.

Do not swallow TLS errors as success.

- [ ] **Step 5: Add 426 defense-in-depth middleware**

For a non-loopback peer observed on any compatibility HTTP path, return:
